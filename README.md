# Student CRUD

A Spring Boot REST API for creating, viewing, updating and deleting students in
MySQL. Each student has a generated ID, name, email address and course.

The Gradle project is inside `student-crud/`. This project uses Gradle rather than
Maven: `build.gradle` defines the build and dependencies; `application.properties`
contains runtime configuration.

## Run in IntelliJ

1. Open `student-crud/build.gradle` as a Gradle project. Use JDK 21 or newer for the
   IDE's Gradle JVM, and install JDK 21 for the project's Java toolchain.
2. Start MySQL. Create the database once in MySQL Workbench:

   ```sql
   CREATE DATABASE IF NOT EXISTS student_db;
   ```

3. In **Run → Edit Configurations**, set these environment variables for
   `StudentCrudApplication`:

   ```text
   DB_USERNAME=your_mysql_username;DB_PASSWORD=your_mysql_password
   ```

   Optionally set `DB_URL` if MySQL is not at
   `jdbc:mysql://localhost:3306/student_db`. The user must have access to this
   database and permission to create/update tables for the default learning setup.
4. Reload Gradle and run `com.example.studentcrud.StudentCrudApplication`.
   If IntelliJ retains an old configuration pointing to `student_crud`, delete
   that run configuration and run the main class from its new package.

The server listens at `http://localhost:8080`. Change `PORT` if necessary.
There is no HTML frontend; use Postman, curl or another API client. Opening
`http://localhost:8080/api/students` in a browser shows the student list as JSON.

## API

| Method | Path | Result |
| --- | --- | --- |
| POST | `/api/students` | Create; returns 201, student and Location header |
| GET | `/api/students` | List students; returns 200 |
| GET | `/api/students/{id}` | Get one; returns 200 or 404 |
| PUT | `/api/students/{id}` | Replace name, email and course; returns 200 or 404 |
| DELETE | `/api/students/{id}` | Delete; returns 204 or 404 |

For POST and PUT, select **Body → raw → JSON** in Postman and send:

```json
{
  "name": "Hari Prasanna",
  "email": "hari@example.com",
  "course": "Java"
}
```

All three fields are required and limited to 255 characters. Email must be valid;
IDs must be positive integers. Invalid requests return 400. IDs are generated by
the database; the request body defines only name, email and course.

## Build and tests

From the inner `student-crud/` directory:

```sh
./gradlew clean build
./gradlew bootRun
```

On Windows use `gradlew.bat` instead. Tests use an isolated in-memory H2 database
in MySQL compatibility mode and need no local MySQL server or credentials. They
exercise the HTTP endpoints through Spring MVC and real JPA persistence. A test
against your actual MySQL server is still needed to verify local access and schema.

Spring Boot 4.1.2 and dependency-management 1.1.7 were already current and are kept.
The Gradle distribution is updated to 9.9.1 with a pinned SHA-256 checksum. Unused
Lombok dependencies were removed. Boot manages the MySQL, validation, logging and
test dependency versions together.

The default `DDL_AUTO=update` is convenient for learning. For a deployed database,
use schema migrations and `DDL_AUTO=validate`. Do not commit real database passwords.
